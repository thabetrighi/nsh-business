# ADR-0006: المزامنة بإعادة تنفيذ حتمية، وقاعدة SQLite لكل مؤسسة على الخادم

- **الحالة:** مقترح — 2026-11-13. يحل محل M11.1–M11.2 (PostgreSQL مشتركة + RLS) في `PLAN.md`.
- **التفاصيل:** `docs/SYNC_PLAN.md`.

## السياق
الأجهزة تعمل كاملاً دون اتصال (بيع، استرجاع، ديون، جولات، جرد) وتكتب كل شيء في SQLite عبر `nb-store`. المطلوب: عدة أجهزة وفروع ومؤسسات لكل عميل، وعملاء كثيرون، مع ضمانات مالية صارمة (لا تكرار، لا فقد، قيود متوازنة، المخزون = الحركات).

## القرار
1. **الخادم يعيد تنفيذ العمليات بشيفرة `nb-store` نفسها** على قاعدة SQLite **مستقلة لكل مؤسسة** (ممثل واحد كاتب لكل مؤسسة). PostgreSQL للوحة التحكم فقط (الحسابات، الأشخاص، الأجهزة، الاشتراكات، الشركاء).
2. **العمليات حتمية:** المعرّفات مشتقة من `operation_id`، والوقت من العملية، والعدادات ببادئة الجهاز؛ والجهاز يرسل بصمة النتيجة للتحقق.
3. **نوعان:** «وقائع» لا تُرفض تجارياً (تُقبل مع بند مراجعة)، و«أوامر» تُعاد بالقواعد الكاملة وقد تُرفض.
4. **السحب** بـ changesets من امتداد session في SQLite مع `server_seq`، وإعادة بناء الإسقاطات بعد التطبيق.
5. **الخادم المحلي** (نفس البرنامج على حاسوب المحل) طبقة اختيارية بين الأجهزة والسحابة.

## البدائل المرفوضة
- **PostgreSQL مشتركة + RLS:** تعني كتابة كل قواعد الأعمال مرتين؛ خطر انحراف القواعد بين الجهاز والخادم.
- **CRDT / cr-sqlite / ElectricSQL / PowerSync:** دمج آلي بآخر كتابة على مستوى الصف؛ ممنوع للمال والمخزون (PRD §8.7).
- **رفع الإيصالات فقط (كما Loyverse وOdoo):** لا يغطي العمل الكامل دون اتصال الذي نعد به.

## العواقب
- عمل تحضيري في العميل قبل الخادم (م0): سجل مدخلات العمليات، حتمية `Writer`، ترحيل العدادات، سلسلة تدقيق لكل جهاز.
- التقارير العابرة للمؤسسات تُبنى بمهام تلخيص على الخادم.
- كل مؤسسة ملف: نسخها واسترجاعها ونقلها وحذفها بسيط.
