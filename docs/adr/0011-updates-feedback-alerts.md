# ADR-0011 — التحديث التلقائي، وصوت المسح واهتزازه، وتنبيه نفاد المخزون، ونسخة واحدة

- **الحالة:** مقبول — 2026-11-15.
- **طلب المالك:** «نعم ابدأ بها»، بعد عرض ما يتيحه NSH 0.5.1 (ADR-0010).

## 1. التحديث التلقائي (سطح المكتب)

### كيف يعمل
- **في `nsh.json`:** `"updater": { "github": "thabetrighi/nsh-business" }`. عند الحزم، يكتب `nsh package` ملف `nsh-updater.json` داخل التطبيق، وفيه المعرّف والإصدار ومصدر التحديث.
- **الإصدارات:** كل بناء لويندوز على GitHub Actions يأخذ الإصدار `0.1.<رقم التشغيل>`، فيكون دائماً أحدث مما قبله. ثم:
  - ينشر إصداراً **كاملاً** (لا تجريبياً) باسم `v0.1.N` ويعلّمه «الأحدث»؛
  - يرفق به ملف التطبيق المضغوط و`latest.json` الذي يولّده `nsh update-manifest`.
  - تبقى نسخة `windows-latest` كرابط تنزيل ثابت.
- **في التطبيق** (`src/updater.rs`):
  1. يقرأ `asset:/nsh-updater.json`.
  2. يجلب `latest.json` من `releases/latest/download`.
  3. يقارن الإصدارين (`Config::check`)، فلا يُعرض أبداً إصدار أقدم.
  4. ينزّل الملف، ويتحقق من SHA-256 وحجمه قبل أي شيء (`Download`).
  5. يضعه مكان التطبيق المثبّت (`Installation::install`).
  6. **لا يعيد التشغيل وحده:** يظهر زر «أعد التشغيل الآن»، فلا ينقطع بيع جارٍ.
- **الإعدادات ← حول التطبيق:**
  - الإصدار الحقيقي للنسخة؛
  - «ابحث عن تحديث»، ثم «نزّل وثبّت»، ثم «أعد التشغيل الآن»؛
  - مفتاح «البحث تلقائياً» (مفعّل افتراضياً): بعد دقيقة من التشغيل ثم كل 12 ساعة. إن وجد إصداراً أظهر رسالة، **ولا يثبّت شيئاً دون إذن.**
- **حالات لا يُحدَّث فيها التطبيق،** وتقول الصفحة ذلك:
  - نسخة التطوير؛
  - تطبيق مثبّت في مجلد لا يُكتب فيه؛
  - الهاتف والمتصفح (يُحدَّثان من المتجر أو بإعادة تحميل الصفحة).

### الأمان
- **HTTPS فقط.** المكتبة ترفض أي عنوان غير HTTPS، إلا عنوان الجهاز نفسه.
- **ملف `latest.json` لتطبيق آخر يُرفض.**
- **ملف لا يطابق SHA-256 لا يُثبَّت.**
- **التثبيت يتحقق من التطبيق الجديد:** أن له معرّف هذا التطبيق وبرنامجه نفسه.
- **غير مفعّل الآن: توقيع `latest.json` بمفتاح Ed25519** (`publicKey`). يحمي من شخص يستولي على حساب GitHub وحده. يحتاج سراً في GitHub يضعه المالك (O-38).

### التجربة
تجربة كاملة على لينكس بخادم محلي وبتوقيع:
1. حزمتان، 0.1.1 و0.1.2.
2. نسخة 0.1.1 مثبّتة وجدت 0.1.2، فنزّلتها وتحققت منها وثبّتتها.
3. بعد إعادة التشغيل عرضت 0.1.2.
4. ملف معدّل البايتات رُفض ولم يتغير التطبيق.

كشفت التجربة خطأً واحداً: إعادة التشغيل بعد التثبيت كانت تغلق التطبيق دون أن تفتحه، لأن مسار البرنامج القديم يزول بعد استبدال المجلد. صار المسار يُحفظ قبل التثبيت (`restart::remember_program`)، وأُعيدت التجربة كاملة فنجحت.

## 2. صوت واهتزاز في نقطة البيع (`ui/feedback.rs`)
- **ثلاثة أصوات قصيرة صُنعت للتطبيق** (`sounds/*.wav`، نحو 60 KB معاً)، مضمّنة فيه وتُفك مرة واحدة عند البدء:
  - صفارة عند إضافة سلعة بالمسح؛
  - نغمتان منخفضتان لرمز غير معروف؛
  - نغمة صاعدة عند تسجيل البيع.
- **على الهاتف اهتزاز:**
  - خفيف عند المسح؛
  - «نجاح» عند الدفع؛
  - «تحذير» عند رمز مجهول؛
  - «خطأ» عند رفض البيع.
- **مفتاحان لهذا الجهاز** في الإعدادات ← الأجهزة: «صوت عند المسح» و«اهتزاز الهاتف»، وكلاهما مفعّل افتراضياً.
- **الضغط على بطاقة سلعة لا يصدر صوتاً.** الصوت للمسح، حيث لا ينظر البائع إلى الشاشة.

## 3. تنبيه نفاد المخزون (`stock_alerts.rs`)
- **بعد كل بيع** تفحص `running_low` (قراءة فقط) السلع التي أخذها البيع وحدها. إن كانت سلعة عند حد إعادة الطلب أو دونه، أو نفدت، **يظهر إشعار من النظام**، مثل: «زيت: بقي 2 (حد إعادة الطلب 5)».
- **لا يتكرر الإشعار لنفس السلعة** حتى يرتفع مخزونها فوق الحد.
- **إذن الإشعارات:** يُطلب عند أول تنبيه.
- **الضغط على الإشعار** يفتح صفحة المخزون.
- **مفتاح في الإعدادات ← الأجهزة.**

## 4. نسخة واحدة على الحاسوب
- `"singleInstance": true`: تشغيل التطبيق مرة ثانية يُظهر النافذة المفتوحة بدل نسخة أخرى. **لا تفتح نسختان القاعدة نفسها.**
- **حدود المنصات:**
  - يعمل في النسخة المحزومة على ويندوز ولينكس؛
  - macOS يفعل ذلك وحده؛
  - لا معنى له على الهاتف والويب.

## العواقب
- **صلاحيات `nsh.json`:** أضيفت `audio` و`notifications`.
- **النسخ الحالية المنزّلة قبل هذا التغيير** لا تعرف مصدر التحديث، فتُنزَّل مرة أخيرة يدوياً. بعدها تُحدّث نفسها.
- **ملاحظات الإصدار:** يحدّث المطوّر `apps/client/release-notes.md` بالعربية مع كل تغيير يهم البائع. تظهر في صفحة GitHub وفي التطبيق.
