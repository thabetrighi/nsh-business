# خادم المزامنة `nb-server` (M11/M1–M2)

خادم واحد صغير بلا تثبيت: ملف تنفيذي لـ Linux أو Windows من إصدار `server-latest` على GitHub. يحتفظ لكل مؤسسة بنسخة SQLite تشغّل قواعد الأعمال نفسها (ADR-0006).

## التشغيل
```bash
NB_SERVER_KEY='مفتاح-تسجيل-طويل-سري' \
NB_SERVER_DIR=/var/lib/nb-server \
NB_SERVER_ADDR=0.0.0.0:8787 \
./nb-server-linux-x86_64
```
على Windows (PowerShell):
```powershell
$env:NB_SERVER_KEY="مفتاح-تسجيل-طويل-سري"; $env:NB_SERVER_DIR="D:\nb-server"; .\nb-server-windows-x86_64.exe
```

| المتغير | المعنى |
|---|---|
| `NB_SERVER_KEY` | **مطلوب.** مفتاح التسجيل (12 حرفاً على الأقل) يكتبه المالك في الجهاز ليربطه أول مرة. احفظه سراً. |
| `NB_SERVER_DIR` | مكان البيانات: `control.sqlite` (المؤسسات والأجهزة) و`tenants/<المؤسسة>.sqlite`. |
| `NB_SERVER_ADDR` | العنوان والمنفذ (افتراضياً `0.0.0.0:8787`). |

## الربط من التطبيق
الإعدادات › المزامنة والنسخ الاحتياطي › الخادم: `https://عنوان-الخادم` + مفتاح التسجيل › **ربط**. يرسل الجهاز قاعدته مرة واحدة، ثم كل عملية كل 20 ثانية (أو «مزامنة الآن»). «تحقق» يقارن بصمة نسخة الخادم ببصمة الجهاز.

## جهاز ثانٍ للمتجر نفسه (م2)
1. على جهاز مرتبط: الإعدادات › المزامنة › **دعوة جهاز** ← يظهر رمز من 8 حروف (صالح ساعة، مرة واحدة).
2. على الجهاز الجديد (تثبيت جديد، شاشة البداية): **الانضمام إلى متجر موجود** ← عنوان الخادم + الرمز ← **انضمام**.
3. يأخذ الجهاز الجديد نسخة الخادم بهويته الخاصة (حرف B ثم C…: أرقام مستنداته `…-B0001` فلا تتصادم الأرقام).

بعدها كل جهاز يرسل عملياته ويأخذ عمليات الآخرين كل 20 ثانية. البيع دون اتصال على جهازين من البضاعة نفسها لا يُرفض: يصبح المخزون سالباً ويُسجَّل **للمراجعة** («نقص مخزون») على كل نسخة، والعدد يظهر في بطاقة المزامنة.

| المسار | المعنى |
|---|---|
| `POST /v1/invite` | رمز دعوة لجهاز جديد (برمز الجهاز) |
| `POST /v1/join` | `{code, name}` ← هوية الجهاز الجديد ورمزه |
| `GET /v1/pull?after=&epoch=` | عمليات الأجهزة الأخرى بعد موضع الجهاز |
| `GET /v1/snapshot` | القاعدة، وموضعها في الترويستين `x-nb-cursor` و`x-nb-epoch` |
| `POST /v1/reseed?after=&epoch=` | إعادة إرسال قاعدة كاملة؛ تُرفض (409) إن لم يكن الجهاز قد أخذ كل ما أرسله غيره، وتبدأ «حقبة» جديدة تجعل الأجهزة الأخرى تأخذ النسخة من جديد مع إبقاء عملياتها غير المرسلة |

## على الإنترنت
ضعه خلف TLS (مثلاً Caddy: `sync.example.dz { reverse_proxy 127.0.0.1:8787 }`). الرموز تُرسل في الترويسات؛ دون TLS تُقرأ في الطريق.

## النسخ الاحتياطي
انسخ مجلد `NB_SERVER_DIR` كاملاً (والخادم متوقف، أو بأداة تدعم SQLite WAL). عند إعادة إرسال قاعدة (`/v1/reseed`) يُحفظ الملف السابق `*.bak` بجانبه.

## الحدود الحالية (م2)
- عملية تحمل سراً (مستخدم بكلمة مرور/PIN) تُرسل كنسخة قاعدة كاملة تلقائياً بعد أخذ عمليات الأجهزة الأخرى. إن أنشأ جهازان مستخدمَين بـ PIN دون اتصال في الوقت نفسه، يتوقف أحدهما برسالة خطأ حتى يُعاد ربطه (حالة نادرة؛ الحل الكامل بنقل بيانات الدخول مجزّأة ضمن العملية في م3).
- قائمة «للمراجعة» تُعرض كعدد فقط؛ شاشة معالجتها لاحقاً.
- الفروع المتعددة والنطاقات (من يرى ماذا) في م3–م4.
- لا لوحة إدارة بعد؛ إلغاء جهاز: احذف صفه من `devices` في `control.sqlite` أو ضع `revoked_at`.
