# خادم المزامنة `nb-server` (M11/M1–M3)

خادم واحد صغير بلا تثبيت: ملف تنفيذي لـ Linux أو Windows من إصدار `server-latest` على GitHub. يحتفظ لكل مؤسسة بنسخة SQLite تشغّل قواعد الأعمال نفسها (ADR-0006).

## التشغيل
```bash
NB_SERVER_KEY='مفتاح-تسجيل-طويل-سري' \
NB_SERVER_DIR=/var/lib/nb-server \
NB_SERVER_ADDR=0.0.0.0:8787 \
./nb-server-linux-x86_64
```
على Windows (PowerShell):
```powershell
$env:NB_SERVER_KEY="مفتاح-تسجيل-طويل-سري"; $env:NB_SERVER_DIR="D:\nb-server"; .\nb-server-windows-x86_64.exe
```

| المتغير | المعنى |
|---|---|
| `NB_SERVER_KEY` | **مطلوب.** مفتاح الخادم (12 حرفاً على الأقل). على خادم خاص (محل، شريك) يطلبه إنشاء حساب جديد. احفظه سراً. |
| `NB_SERVER_OPEN_SIGNUP` | `1` لخادم عام: أي تاجر يُنشئ حسابه دون المفتاح. |
| `NB_SERVER_KEEP_DAYS` | النسخ اليومية المحفوظة لكل متجر (افتراضياً 14) في `backups/`. |
| `NB_SERVER_ALLOW_ORIGINS` | عنوان تطبيق الويب (`https://app.example.dz`، وعدة عناوين بفواصل) المسموح له بمخاطبة الخادم من المتصفح. فارغ = لا متصفح. |
| `NB_SERVER_TRUST_PROXY` | `1` خلف Caddy أو مثله: عنوان المتصل يؤخذ من `X-Forwarded-For` لحدود التخمين. |
| `NB_SERVER_DIR` | مكان البيانات: `control.sqlite` (المؤسسات والأجهزة) و`tenants/<المؤسسة>.sqlite`. |
| `NB_SERVER_ADDR` | العنوان والمنفذ (افتراضياً `0.0.0.0:8787`). |

## الحساب والربط من التطبيق (ADR-0007)
الإعدادات › المزامنة والنسخ الاحتياطي:
- **حساب جديد:** عنوان الخادم + الاسم + رقم الهاتف + كلمة مرور (8 أحرف على الأقل) + مفتاح الخادم (لخادم خاص فقط) › **إنشاء الحساب وربط هذا المتجر**. تظهر **10 رموز استرجاع مرة واحدة**: اكتبها أو صوّرها واحفظها بعيداً عن الجهاز.
- **دخول:** لحساب موجود › **دخول وربط هذا المتجر**.

يرسل الجهاز قاعدته مرة واحدة، ثم ما يحدث فيه خلال ثانيتين، ويسمع بما ترسله الأجهزة الأخرى **فوراً عبر WebSocket** (`/v1/ws`): بيع على جهاز ظهر على الآخر بعد ثانيتين في التجربة، وعاد الاتصال وحده بعد إعادة تشغيل الخادم. إن انقطع WebSocket ينتظر الجهاز بطلبات `/v1/wait` حتى يعود. «تحقق» يقارن بصمة نسخة الخادم ببصمة الجهاز.

**نسيت كلمة المرور:** «نسيت كلمة المرور» في البطاقة نفسها: الهاتف + أحد رموز الاسترجاع + كلمة جديدة (كل رمز مرة واحدة؛ الجلسات القديمة تنتهي). بعد 8 محاولات خاطئة ينتظر الحساب ربع ساعة.

| المسار | المعنى |
|---|---|
| `POST /v1/signup` · `/v1/login` · `/v1/recover` | الحساب (الهاتف + كلمة المرور، رموز الاسترجاع) |
| `GET /v1/orgs` | متاجر الحساب |
| `POST /v1/orgs/{id}/devices` | جهاز جديد لأحد متاجر الحساب دون رمز دعوة |
| `GET /v1/wait?after=&epoch=` | ينتظر حتى يرسل جهاز آخر شيئاً (25 ث على الأكثر)؛ البديل حين لا يعمل WebSocket |
| `GET /v1/ws` | WebSocket: `{"ready":true}` ثم `{"changed":true}` كلما أرسل جهاز آخر. الرمز في `Authorization`، أو أول رسالة `{"token":…}` من المتصفح |
| `GET /v1/orgs/{id}/devices` | أجهزة متجر الحساب (لاختيار الجهاز الذي يحل محله تثبيت جديد) |

## جهاز ثانٍ للمتجر نفسه (م2)
على الجهاز الجديد (تثبيت جديد، شاشة البداية): **الانضمام إلى متجر موجود** ← عنوان الخادم، ثم:
- **بحسابي:** الهاتف + كلمة المرور ← اختر المتجر من القائمة (صاحب الحساب)؛ أو
- **برمز دعوة:** من جهاز مرتبط: الإعدادات › المزامنة › **دعوة جهاز** ← رمز من 8 حروف (ساعة، مرة واحدة) — لجهاز موظف دون إعطائه كلمة مرور الحساب.
3. يأخذ الجهاز الجديد نسخة الخادم بهويته الخاصة (حرف B ثم C…: أرقام مستنداته `…-B0001` فلا تتصادم الأرقام).

بعدها كل جهاز يرسل عملياته ويأخذ عمليات الآخرين كل 20 ثانية. كل جهاز منضم يُنشئ **صندوقه** («صندوق الجهاز B») فيفتح درجه ويغلقه وحده.

ما حدث عند الصندوق لا يُرفض حين يلتقي جهازان كانا دون اتصال؛ يُقبل ويظهر في بطاقة **«للمراجعة»** (الإعدادات › المزامنة) حتى يعلّمه أحد «تمت المراجعة» (فيُعلَّم على كل الأجهزة):
- **نقص مخزون:** البضاعة نفسها بيعت على جهازين.
- **استرجاع مكرر:** البيع نفسه استُرجع على جهازين.
- **نقص في الصندوق:** دُفع نقداً من صندوق لم يعد فيه ما يكفي.
- **عملية رفضها الخادم:** لم تعد ممكنة بعدما سبقتها عمليات جهاز آخر (مثلاً استلام التحويل نفسه على جهازين). تُلغى على الجهاز (يأخذ نسخة الخادم ويعيد تنفيذ ما سواها) ولا تُرسل مرة أخرى.

**الفروع على أجهزة مختلفة (م3):** تحويل يُرسل من مستودع فرع على جهازه، ويستلمه الفرع الآخر على جهازه لاحقاً دون أن يكونا متصلين معاً؛ النقص عند الاستلام خسارة مخزون كالعادة.

**دون اتصال طويلاً:** بعد 7 أيام دون مزامنة ناجحة يظهر «دون مزامنة منذ أيام» أعلى الشاشة؛ بعد 14 يوماً تنتظر الإعدادات والمستخدمون والصلاحيات المزامنة على الجهاز المرتبط. البيع لا يتوقف أبداً.

**الأجهزة:** الإعدادات › المزامنة › الأجهزة ← كل جهاز بحرفه واسمه وآخر ظهور؛ «إيقاف» (ضغطتان) لجهاز ضائع أو مستبدل: رمزه لا يفتح شيئاً بعدها.

| المسار | المعنى |
|---|---|
| `POST /v1/invite` | رمز دعوة لجهاز جديد (برمز الجهاز) |
| `POST /v1/join` | `{code, name}` ← هوية الجهاز الجديد ورمزه |
| `GET /v1/pull?after=&epoch=` | عمليات الأجهزة الأخرى بعد موضع الجهاز |
| `GET /v1/snapshot` | القاعدة، وموضعها في الترويستين `x-nb-cursor` و`x-nb-epoch` |
| `GET /v1/devices` · `POST /v1/devices/{id}/revoke` | أجهزة المؤسسة، وإيقاف جهاز |
| `POST /v1/reseed?after=&epoch=` | **إصلاح فقط:** استبدال قاعدة المتجر كاملة. يتطلب رمز الجهاز **وجلسة حساب عضو في المتجر** (`x-account`)، ويُرفض (409) إن لم يكن الجهاز قد أخذ كل ما أرسله غيره. يبدأ «حقبة» جديدة تأخذ بها الأجهزة الأخرى النسخة مع إبقاء عملياتها غير المرسلة |

## إعادة تثبيت التطبيق
على الجهاز بعد إعادة التثبيت: الانضمام إلى متجر موجود ← بحسابي ← المتجر ← اختر **الجهاز القديم** من القائمة. يعود حرفه وصندوقه، ويستمر ترقيمه بعد آخر رقم يعرفه الخادم، ويتوقف رمز التثبيت القديم فوراً. ما لم يُرسل قبل الحذف لا يعود.

## الويب
تطبيق الويب يحفظ نسخة المتجر في IndexedDB الخاص بالمتصفح (تُحفظ بعد كل تغيير بثوانٍ، وتُفتح عند العودة)، ويتزامن مع الخادم كالتطبيقات الأخرى (WebSocket من المتصفح). على الخادم ضع عنوان تطبيق الويب في `NB_SERVER_ALLOW_ORIGINS`. على حاسوب مشترك: فك الربط بعد العمل.

## منصة الإدارة (ADR-0008)
1. أنشئ مشرفاً على الخادم نفسه:
   ```
   NB_SERVER_DIR=… nb-server admin add boss "اسمك"
   ```
   يطلب كلمة مرور (12 حرفاً على الأقل)، ثم يعرض رمز QR: امسحه بتطبيق رموز (Google Authenticator أو Aegis).
2. شغّل الخادم كالعادة. المنصة على `127.0.0.1:8789` (أي الخادم نفسه فقط).
3. من حاسوبك:
   ```
   ssh -L 8789:127.0.0.1:8789 server
   ```
   ثم افتح `http://127.0.0.1:8789/admin/`.
4. **أوامر أخرى:**
   - `nb-server admin list`
   - `reset-2fa <login>` (هاتف ضائع)
   - `password <login>`
   - `disable <login>` و`enable <login>`
   - `unlock <login>`
5. **المتغيرات:**
   - `NB_ADMIN_ADDR`: عنوان المنصة، و`off` لإغلاقها.
   - `NB_ADMIN_ALLOW_IPS`: حصرها بعناوين أو شبكات.
   - `NB_SERVER_BILLING=1`: فرض الاشتراكات (تجربة، ومهلة، وحد الأجهزة). دونه لا يُوقف إلا متجر أوقفه المشرف يدوياً.
6. **بيانات للتجربة:**
   ```
   NB_SEED_DIR=/tmp/demo cargo test -p nb-server --test admin -- --ignored seed
   ```
   المشرف `boss`، ومفتاح تطبيق الرموز في `/tmp/demo/admin-key.txt`.

## الأمان
التفاصيل والمخاطر المقبولة في `docs/SECURITY.md`.

## على الإنترنت (داخل الجزائر، ADR-0007)
- **المزوّد:** VPS في مركز بيانات جزائري (ICOSNET أو Algérie Télécom مثلاً؛ 1 vCPU و2–4 GB تكفي عشرات المتاجر). لا سحابة أجنبية لبيانات الزبائن (القانون 18-07).
- **TLS إلزامي:** مثلاً Caddy: `sync.example.dz { reverse_proxy 127.0.0.1:8787 }`. الرموز وكلمات المرور تمر في الطلبات؛ دون TLS تُقرأ في الطريق.
- خدمة systemd تعيد تشغيله، و`NB_SERVER_DIR` على قرص مستقل.

## النسخ الاحتياطي
- **تلقائي:** نسخة يومية لكل متجر في `NB_SERVER_DIR/backups/<المتجر>/<التاريخ>.sqlite`، آخر 14 يوماً (`NB_SERVER_KEEP_DAYS`). كل نسخة قاعدة كاملة تُفتح بالتطبيق نفسه.
- **خارج الخادم:** انسخ `backups/` يومياً إلى مزوّد جزائري ثانٍ مشفّراً (مثلاً `restic` أو `rclone crypt`)، و`control.sqlite` معه.
- عند إعادة إرسال قاعدة (`/v1/reseed`) يُحفظ الملف السابق `*.bak` بجانبه.

## الحدود الحالية (م3)
- الجهاز يحمل متجراً واحداً: صاحب متجرين يستعمل جهازاً (أو تثبيتاً) لكل متجر؛ التبديل بين المتاجر على الجهاز نفسه لاحقاً.
- النطاقات (هاتف السائق يحمل جزءاً فقط) في م4.
- لا لوحة إدارة للخادم بعد (المؤسسات والحسابات تُرى في `control.sqlite`).
